# AI-Powered Resume Screener & Job Matcher

A 4-layer pipeline that ranks resumes against job descriptions, enriches
them with structured data, scores/explains fit using AI agents, and
automatically emails rejected candidates — all wrapped in one Streamlit
app for a live demo.

```
Layer 1 (ML)      TF-IDF + cosine similarity        -> resume-to-job ranking
Layer 2 (NLP)     regex + spaCy PhraseMatcher        -> structured fields, skills
Layer 3 (Agents)  CrewAI + Groq (llama-3.3-70b)      -> fit score + explanations
Layer 4 (Email)   smtplib                             -> automated rejection emails
```

## Project structure

```
project/
├── requirements.txt        ← install this once, covers everything
├── .env.example             ← copy to .env, fill in your keys (shared by all layers)
├── app.py                   ← ⭐ the Streamlit app — start here for a live demo
├── pipeline/
│   ├── ml_ranking.py         (Layer 1 logic, importable)
│   └── nlp_enrichment.py     (Layer 2 logic, importable)
├── agents/
│   ├── crew_agents.py        (Layer 3: agent/task/tool definitions)
│   ├── run_agents.py         (Layer 3: CLI batch runner)
│   └── README.md             (Layer 3 CLI usage)
├── email/
│   ├── send_rejections.py    (Layer 4: CLI email dispatcher)
│   └── README.md             (Layer 4 CLI usage)
├── notebooks/
│   └── data.ipynb            (original ML+NLP development notebook)
└── data/
    ├── resumes.csv
    ├── job_descriptions.csv
    └── (ranked_candidates.csv / enriched_candidates.csv / scored_candidates.csv
         are generated by the app / scripts — not included, so you always
         start from a clean state)
```

## Setup (one-time)

```bash
pip install -r requirements.txt
python -m spacy download en_core_web_sm   # optional — enables company-name NER;
                                            # everything else works without it
cp .env.example .env
```

Edit `.env`:
- `GROQ_API_KEY` — free key at https://console.groq.com/keys
- `SMTP_USERNAME` / `SMTP_PASSWORD` — for Gmail, use an **App Password**
  (not your normal password): https://myaccount.google.com/apppasswords
- `TEST_OVERRIDE_EMAIL` — **strongly recommended** while demoing: set this
  to your own inbox so every "rejection email" actually lands somewhere
  you can see it, instead of the dataset's fake `@example.com` addresses.

## Run the app

```bash
streamlit run app.py
```

Opens in your browser. Four tabs, meant to be used in order for a first
run:

1. **📊 Rank & Enrich** — runs Layers 1+2 on the bundled dataset (or your
   own uploaded CSVs). Click "Run ML + NLP Pipeline." Shows ranked
   candidates per job and a validation chart (match score vs. the
   dataset's ground-truth `fit_level`).
2. **🎯 Live Candidate Test** — paste a resume or upload a PDF, pick a
   job, and see an instant TF-IDF score + extracted fields. Optional
   button to run that one candidate through the real CrewAI agents.
3. **🤖 Agent Scoring** — batch-runs the CrewAI pipeline (Screening →
   Scoring → Feedback → Bias-Check) over the enriched candidates. A
   slider controls how many per job get processed, to control Groq API
   usage during a demo.
4. **✉️ Rejection Emails** — previews every message that would be sent,
   requires an explicit confirmation checkbox before the "Send" button
   is even clickable, and logs delivery status back into the data.

The sidebar shows pipeline status (what's been generated so far) and lets
you paste in `GROQ_API_KEY` / SMTP credentials directly for the session if
you'd rather not use a `.env` file during a live demo.

## Using each layer standalone (without the app)

Each layer also works as a command-line script, independent of Streamlit
— see `agents/README.md` and `email/README.md` for CLI usage
(`run_agents.py --all`, `send_rejections.py --send`, etc). Both the CLI
scripts and `app.py` call the exact same underlying functions
(`pipeline/`, `agents/crew_agents.py`), so results are identical either
way — the app is just a UI on top of the same code.

## Known scope notes (good material for a "future work" section)

- **PDF resume parsing** (Tab 2) extracts skills reliably from any text,
  but structured fields (education/experience/certifications) are parsed
  via section-header regex tuned to this dataset's template — a resume
  that doesn't follow a `Name/Email/Phone` + `EDUCATION`/`SKILLS`/...
  section layout will still get a TF-IDF match score and skill list, just
  fewer structured fields.
- **No authentication / multi-user support** — this is a single-operator
  demo tool, not a deployed multi-tenant product.
- **CSV-based storage** — fine for a project this size; a real deployment
  would swap this for a database (see the deployment discussion earlier
  in this project's build for what a production version would add:
  backend API, database, background job queue, hosted secrets).
- **`REJECTION_THRESHOLD = 50`** in `agents/run_agents.py` is a starting
  point — once you've run real Groq-scored candidates, check the actual
  `fit_score` distribution and tune it.
